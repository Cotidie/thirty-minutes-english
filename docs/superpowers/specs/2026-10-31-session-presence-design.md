# 세션 안에서 서로의 존재 느끼기 설계

작성일: 2026-10-31

## 왜 만드는가

이 앱은 두 사람이 30분 동안 영어로 이야기하는 도구다. 지금은 같은 세션을 열어 둬도 상대가 어디를 보고 무엇을 눌렀는지 알 수 없다. 저장되는 것(별표, 노트, 연습 기록)만 실시간으로 맞고, 화면에서 뒤집어 본 것은 각자의 브라우저에만 남는다.

세션 안에서 상대의 마우스가 움직이고 상대가 누른 것이 내 화면에서도 똑같이 뒤집히면, 떨어져 있어도 같은 종이를 함께 보는 느낌이 난다. 성공 기준은 데이터가 맞는 것이 아니라 "같이 있구나" 하고 느끼는 것이다.

## 범위

### 사용자가 정한 것

- 세션 화면 안에서는 서로의 마우스 위치가 항상 실시간으로 보인다. 켜고 끄는 설정은 없다.
- 상대가 다른 탭에 있으면 그 탭을 알려 주는 표시가 나온다.
- 사람은 색으로 구분한다.
- 상대가 화면 요소를 누르면 내 화면에도 똑같이 적용된다. 적용 범위는 아래 표다.
- 타이머를 공유한다. 한 사람이 시작, 일시정지, 재개, 초기화하면 모두에게 적용되고, 늦게 들어온 사람도 같은 시간을 본다.
- 타이머는 시간만 잰다. 10분이 지나도 탭을 옮기지 않는다.
- 탭 이동과 스크롤은 따라가지 않는다. 상대 커서가 화면 밖에 있으면 위나 아래 가장자리에 표시한다.
- 이름이나 이메일은 표시하지 않는다. 폰은 마우스가 없으니 상대 커서를 보기만 한다.
- 브라우저는 `partysocket`, 서버는 FastAPI 내장 WebSocket을 쓴다.

### 똑같이 적용되는 것

| 화면 요소 | 지금 상태가 있는 곳 |
|---|---|
| 표현과 단어의 한글 칩 | `KoreanChip.shown` |
| 한국어 카드 뒤집기 | `ExpressionsTab`의 `KoreanExample.english` |
| 단어 뜻 펼치기 | `VocabCard.revealed` |
| 그림 뒤집기 (Example, Practice) | `VocabCell.flipped` |
| 장면 설명 | `SceneCaption.shown` |
| 기사 문장의 한국어 전환 | `Sentence.lang` |
| 토론 질문 선택 (근거 문장 표시) | `ArticleTab.active` |
| 타이머 시작, 일시정지, 재개, 초기화 | `SessionTimer.running`, `elapsed` |

### 하지 않는 것

- 마이크 녹음 시작: 상대의 클릭으로 내 마이크가 켜지면 안 된다. `ArticleTab.reading`, `ReadAloud`, `Practice`, `Summarize`의 녹음은 대상이 아니다.
- 음성 재생(`SpeakButton`): 통화 중이면 소리가 겹친다.
- 입력창 타자, 노트 창 열기(`NoteBox.open`), 공유 관리, 설정.
- 이미 REST와 세션 스트림으로 맞는 것은 건드리지 않는다: 별표, 노트 내용, 표현 교체와 추가, 그림 다시 그리기, 연습 기록.
- 홈 화면의 접속 표시, 접속 기록, 통계. 커서와 접속 정보는 어디에도 저장하지 않는다.
- 많은 인원 지원. 한 세션에 몇 명이면 충분하고 앱은 지금처럼 프로세스 하나로 돈다.

### 실패로 볼 것

아래 중 하나라도 일어나면 기능이 돌아가도 실패다.

- 상대의 행동으로 내 마이크가 켜지거나 내 스피커에서 소리가 난다.
- 커서 메시지 때문에 세션 화면 전체가 다시 그려져 입력이나 스크롤이 버벅인다.
- 같은 칩이 두 화면에서 번갈아 열리고 닫힌다.
- 다른 공유자의 이메일이나 계정 번호가 메시지에 실린다.
- 웹소켓이 끊기거나 막혔을 때 세션의 다른 기능이 멈춘다. 끊겨도 칩, 카드, 타이머는 지금처럼 혼자서 동작해야 한다.

## 통신 규칙 변경

지금 규칙은 "REST가 모든 상태를 맡고, 스트림은 이름만 나른다"이다. 커서는 초당 여러 번 바뀌므로 이 방식이 맞지 않는다. 세 번째 통로를 하나 더하고 경계를 분명히 한다.

**현존감(presence) 통로:** `WS /api/sessions/{id}/presence`. 누가 와 있는지, 커서 위치, 보고 있는 탭, 뒤집어 본 화면 요소, 타이머만 나른다. 이 통로의 내용은 저장하지 않는다. 판단 기준은 "서버가 재시작해 사라져도 다시 뒤집으면 그만인가"이다. 사라지면 안 되는 것은 지금처럼 REST와 이벤트로 간다.

`CLAUDE.md`, `AGENTS.md`의 Client-server communication 절과 `2026-10-30-accounts-and-sharing-design.md`의 "통신의 경계" 표를 이 내용으로 고친다. 뒤집어 본 상태와 타이머는 지금도 새로고침하면 사라지는 값이므로 저장 대상이 아니다. (이 경계는 설계자의 판단이다.)

## 서버

### 라우트와 권한

- 지금 라우터는 `dependencies=[Depends(signed_in)]`로 묶인다. `signed_in`은 `Request`를 받는데 FastAPI는 웹소켓 라우트에 `Request`를 주입하지 않아 그대로 넣으면 실패한다. `public_router`처럼 그 의존성 없이 따로 등록하고 라우트 안에서 직접 검사한다.
- 연결할 때 로그인 쿠키(`LOGIN_COOKIE`)와 `db.shares.can_access`를 확인한다. 통과하기 전에는 어떤 데이터도 보내지 않는다.
- **Origin 검사가 필수다.** 웹소켓에는 동일 출처 정책이 적용되지 않는다. `Origin` 헤더가 있으면 그 호스트가 `Host` 헤더와 같아야 한다. `Origin`이 없는 요청(브라우저가 아닌 클라이언트)은 로그인 검사만 받는다. 안쪽 nginx의 `/api/`는 `Host`를 넘기지 않으므로 이 경로의 `location`에서 `proxy_set_header Host $http_host`를 준다. `$host`는 포트를 떼어 `127.0.0.1:5173` 같은 직접 접속의 `Origin`과 어긋난다.
- 접속 중에도 권한을 다시 본다. `db.changes.subscribe(session_id)`로 `ACCESS`를 듣고, 25초마다도 로그인과 접근권을 확인한다. 없어졌으면 연결을 닫는다. 세션 스트림의 `events_of`와 같은 판단을 재사용한다.
- 거절은 클라이언트가 구별할 수 있어야 한다. 자동 재연결이 끝없이 돌지 않도록, 권한 없음으로 닫힌 뒤에는 다시 연결하지 않는다. (닫는 코드와 시점은 구현자 재량)

### 방

`app/live/presence.py`에 웹 프레임워크를 모르는 방 목록을 둔다. `app/live/changes.py`와 같은 위치와 성격이다. 이벤트 루프 안에서만 만지므로 잠금이 필요 없다.

방 하나가 가지는 것:

- 접속자: 연결마다 임의의 연결 id, 계정 번호(서버 내부 전용), 색 번호, 탭, 마지막 커서
- 화면 상태: 키에서 값으로 가는 사전
- 타이머: 진행 여부, 경과 시간, 그 값을 받은 시각

방은 마지막 사람이 나간 뒤 10분 동안 남았다가 사라진다. 혼자 새로고침해도 타이머가 초기화되지 않게 하기 위해서다. 서버가 재시작하면 모두 사라진다. (10분은 설계자의 판단이다.)

### 색 번호

세션에 관련된 계정 순서로 정한다: 만든 사람이 0번, 그다음 공유받은 사람을 계정 번호 순으로. 목록에 없는 운영자는 다음 빈 번호를 받는다. 같은 세션 안에서는 겹치지 않고, 다시 들어와도 같은 색이다. 팔레트 크기를 넘으면 처음부터 돈다.

### 메시지

JSON 텍스트 프레임이다. 필드 이름은 구현자 재량이고 담기는 내용은 아래와 같다.

| 방향 | 종류 | 내용 |
|---|---|---|
| 서버에서 나에게 | 입장 | 내 연결 id와 색, 다른 사람들(연결 id, 색, 탭), 화면 상태 전체, 타이머 |
| 서버에서 모두에게 | 들어옴, 나감 | 연결 id, 색, 탭 |
| 양방향 | 커서 | 탭, 기준 요소 id, 그 요소 안에서의 비율 x, y. 또는 "커서 없음" |
| 양방향 | 탭 | 탭 번호 |
| 양방향 | 화면 상태 | 키, 값 |
| 양방향 | 타이머 | 진행 여부, 경과 초 |

규칙:

- 메시지에 계정 번호나 이메일을 넣지 않는다. 연결 id와 색만 나간다.
- 같은 계정의 다른 연결에는 커서와 탭을 보내지 않는다. 내 다른 탭의 커서가 내 화면에 보이면 안 된다. 화면 상태와 타이머는 보낸다. (설계자의 판단이다.)
- 운영자도 다른 사람과 똑같이 보인다. 보이지 않는 관찰자는 만들지 않는다. (설계자의 판단이다.)
- 값 기반이다. "눌렀다"가 아니라 "이 키의 값은 이것이다"를 보낸다. 그래서 두 번 받아도 같고, 받은 쪽이 다시 보내지 않는다.
- 동시에 누르면 서버가 나중에 받은 값이 모두의 화면에서 이긴다. 그러려면 화면 상태와 타이머는 서버가 받은 순서대로 보낸 사람에게까지 돌려보낸다. 다른 사람에게만 전달하면 두 사람이 서로의 값으로 뒤바뀐 채 굳는다. 내 값이 돌아오기 전에 받은 다른 사람의 값은 무시해서 화면이 깜박이지 않게 한다. (설계자의 판단이다.)
- 서버는 검증한다: 프레임 크기 상한, 알려진 종류만, 키 형식과 값 형식(불리언, 숫자, 짧은 문자열, null), 비율 범위, 방당 키 개수 상한, 연결당 커서 수신 상한을 넘으면 버린다.
- 느린 사람이 다른 사람을 막지 않는다. 연결마다 보낼 것을 따로 두고, 커서는 보낸 사람별 최신 값만 남긴다. `Subscription`이 이벤트를 집합으로 합치는 것과 같은 생각이다.

타이머는 값 기반이므로 재시작한 서버의 방에 타이머가 없으면, 타이머가 돌고 있던 클라이언트가 자기 값을 다시 보낸다. 화면 상태는 다시 보내지 않는다. 재시작 뒤에 뒤집어 둔 칩이 닫히는 것은 괜찮다. 진행 중인 타이머가 사라지는 것은 괜찮지 않다.

## 프록시

- 안쪽 `frontend/nginx.conf`에 `location ~ ^/api/sessions/[0-9]+/presence$`를 더한다: `proxy_http_version 1.1`, `Upgrade`, `Connection "upgrade"`, `Host $http_host`, 긴 `proxy_read_timeout`.
- 바깥 nginx(`lab-server`)는 `snippets/proxy.conf`에서 이미 `Upgrade`를 통과시키므로 고치지 않는다. `proxy_read_timeout 600s`는 uvicorn의 기본 웹소켓 핑(20초)이 넘지 않게 한다.
- `frontend/vite.config.ts`의 프록시를 `{ target, ws: true }` 형태로 바꾼다.
- Cloudflare 통과는 배포 전에는 확인할 수 없다. 공개 주소는 이 저장소의 스택으로만 이어지고, 지금 스택에는 웹소켓 라우트가 없다. 그래서 먼저 안쪽 nginx를 포함한 별도 스택에서 검증하고, **배포 직후 공개 주소로 확인한다.** 막혀 있어도 세션은 지금처럼 혼자서 동작하며, 그때는 Cloudflare 대시보드의 WebSockets 설정을 사용자에게 알린다. (설계자의 판단이다.)

## 브라우저

### 구조

- **연결은 한 곳에서만 만든다.** `lib/presence/` 아래 한 모듈만 `partysocket`을 쓴다. `sessionChanges.ts`가 `EventSource`를 독점하는 것과 같다. 옵션 `maxEnqueuedMessages: 0`으로 끊긴 동안의 메시지를 버린다. 기본값은 무제한이라 재연결 때 옛 위치가 쏟아진다.
- **프로바이더:** `SessionPage`에서 `OpenSession`을 감싼다. 세션이 사라져 알림 화면으로 바뀌면 함께 내려가 연결이 닫힌다. `key={id}`로 세션을 옮길 때 새로 연결한다.
- **`useSharedView(key, initial)`:** 위 표의 `useState`를 이것으로 바꾼다. 쓰면 내 화면에 바로 반영하고 보낸다. 받으면 그 키를 쓰는 컴포넌트만 다시 그린다(`useSyncExternalStore`). 프로바이더가 없으면 평범한 지역 상태로 동작해 기존 컴포넌트 테스트가 그대로 돈다.
- **커서 그리기:** 세션 화면 위에 `pointer-events: none`인 고정 레이어 하나를 두고 `transform`을 직접 고친다. 커서 메시지로 React 상태를 바꾸지 않는다. 스크롤과 창 크기 변화에 맞춰 위치를 다시 계산한다.
- **연결이 끊겨도** `useSharedView`와 타이머는 지역 상태로 계속 동작한다. 끊김 표시는 하지 않는다. 다시 붙으면 서버의 화면 상태를 따른다.

### 커서 위치

창 크기가 달라도 같은 곳을 가리키도록 기준 요소와 그 안에서의 비율을 보낸다.

- 기준 요소에는 양쪽 화면에서 같은 값이 나오는 안정된 id를 붙인다: 표현 카드, 단어 칸, 기사 문단, 토론 질문, 탭 안내문, 레일의 각 부분(타이머, 탭 목록, 공유 패널). 내용 영역 전체를 마지막 기준으로 둔다.
- 받은 쪽에 그 요소가 없거나 탭이 다르면 커서를 그리지 않는다.
- `pointermove`에서 `pointerType === 'mouse'`만 보낸다. 폰의 터치가 커서로 보내지지 않게 하기 위해서다. 초당 약 20번으로 줄여 보낸다. 스크롤로 커서 아래 요소가 바뀌면 다시 보낸다.
- 마우스가 창을 벗어나거나 페이지가 숨겨지면 "커서 없음"을 보낸다.
- 받는 쪽은 메시지 사이를 짧게 보간해 부드럽게 움직인다. `prefers-reduced-motion`이면 보간하지 않는다. 상대 커서가 화면 밖이면 그 사람의 색으로 위나 아래 가장자리에 화살표를 둔다.
- 커서 레이어는 `aria-hidden`이다. 코너 버튼(`z-index: 20`)보다 아래에 둔다.

### 탭 표시

레일의 탭 목록(`.tabs .tab`)에서 다른 사람이 있는 탭 줄에 그 사람 색의 작은 점을 둔다. 같은 탭에 있어도 표시한다. 여러 명이면 나란히 둔다. 화면 낭독기를 위해 그 줄에 "다른 사람이 여기 있다"는 레이블을 준다. Summary 탭도 포함한다.

### 색

`base.css`에 `--person-1`부터 여섯 개의 토큰을 더한다. 이미 뜻이 있는 색(`--marker` 노랑, `--error` 빨강, `--right` 초록, `--phrase` 남색)과 헷갈리지 않아야 하고, `--paper` 위에서 대비가 3:1 이상이어야 한다. 앱에 어두운 테마는 없다. 값은 구현자 재량이다.

### 화면 상태 키

양쪽에서 같아야 하므로 내용의 id로 만든다.

| 요소 | 키 |
|---|---|
| 표현 한글 칩 | `chip:expression:{id}` |
| 단어 한글 칩 | `chip:word:{id}` |
| 한국어 카드 | `example:{표현 id}` |
| 단어 뜻 | `reveal:{단어 id}` |
| 그림 면 | `face:{단어 id}` |
| 장면 설명 | `caption:{단어 id}` |
| 기사 문장 | `sentence:{문단 id}:{문단 안 시작 위치}` |
| 토론 질문 | `question` (선택된 번호 또는 null) |

`KoreanChip`은 지금 `korean`과 `of`만 받으므로 키를 넘겨받도록 바꾼다.

### 컴포넌트별 주의점

- **`Sentence`:** 언어가 애니메이션 끝에서 바뀐다. 받은 값이 지금 언어와 다르면 내가 누를 때와 같은 애니메이션을 돌린다. 애니메이션 도중에 값이 다시 오면 끝난 뒤 최신 값으로 맞춘다.
- **`ArticleTab.active`:** 값이 바뀌면 근거 문장으로 `scrollIntoView`한다. 스크롤은 공유하지 않으므로 **직접 누른 사람만 스크롤한다.** 받은 쪽은 표시만 바뀐다. (설계자의 판단이다.)
- **`SceneCaption`:** `key={image}`로 그림이 바뀌면 상태가 초기화된다. 공유 키로 바꾼 뒤에도 그림을 뒤집거나 다시 그리면 설명이 닫히게 한다.
- **`SessionTimer`:** 받은 값(진행 여부, 경과 초)에서 각자 1초씩 센다. 시작, 일시정지, 재개, 초기화는 내 화면에 바로 반영하고 값을 보낸다. 끝난 뒤의 상한은 지금처럼 `SESSION_SECONDS`로 자른다.
- **타이머와 탭:** 타이머의 자동 탭 이동은 0.5.8에서 없앴다. 공유 타이머에도 넣지 않는다. 탭이 저절로 바뀌지 않으므로 타이머 때문에 녹음이 끊기는 일도 없다.

## 검증

- **서버(pytest):** 방의 입장과 퇴장, 입장 메시지 내용, 색 번호 규칙, 화면 상태와 타이머 스냅샷, 메시지 검증과 상한, 커서 합치기, 메시지에 계정 번호와 이메일이 없음, 로그인 없음과 접근권 없음과 다른 Origin의 거절, 공유가 끝나면 연결이 닫힘.
- **브라우저(vitest):** `FakeEventSource`처럼 가짜 웹소켓을 둔다. `useSharedView`의 쓰기, 받기, 프로바이더 없는 동작, 받은 값을 되돌려 보내지 않음. 타이머의 값 동기화와 구간 경계를 넘어도 탭이 그대로임. 커서 메시지가 React 렌더를 일으키지 않음.
- **실제 브라우저 두 개(Playwright, 저장소 밖 임시 스크립트):** 창 크기가 다른 두 브라우저에서 커서가 같은 요소를 가리킴, 탭 점, 표의 모든 화면 요소 동기화, 타이머 공유, 웹소켓을 끊어도 세션 기능이 동작함, 상대 클릭으로 마이크나 소리가 나지 않음.
- **배포 후:** 공개 주소에서 웹소켓 연결과 메시지 왕복을 확인한다.

## 구현자 재량

모듈과 파일 이름, 메시지 필드 이름, 닫는 코드, 커서 모양과 색 값, 탭 점의 크기와 위치의 세부, 보간 방식, 각 상한의 수치. `partysocket`은 최신 안정판을 쓰고 `package-lock.json`을 함께 고친다. 새 Python 의존성은 없다. 병합 후에는 패치 버전만 올린다.
