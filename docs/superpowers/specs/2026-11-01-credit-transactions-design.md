# 크레딧 트랜잭션 설계

- 상태: 구현됨 (2026-11-01).
- 범위: 크레딧을 쓰는 모든 기능을 "완수해야 차감"으로 바꾼다. 스키마 v14.
- 대체하는 문서: `2026-11-01-credits-design.md`의 "차감 뒤 제공자 실패는 돌려주지 않는다", 세션 생성의 환불 규칙. 가격표, 잔액 표시, 충전은 그 문서 그대로다.
- 구현 계획: `docs/superpowers/plans/2026-11-01-credit-transactions.md`

## 목적

크레딧은 기능을 시작할 때 차감되고, 세션 생성의 "글 저장 전 실패"만 돌려준다. 나머지 유료 기능은 제공자가 실패해도 차감이 남는다. 사용자는 이를 뒤집어, 오류가 나거나 기능을 완수하지 못하면 차감하지 않기를 원한다. 다만 사용자가 일부러 멈춘 세션 생성은 Claude 사용량을 이미 썼으므로 절반을 받는다. 일부러 구독량을 소모시키는 사람을 막기 위해서다.

## 점검 결과: 이 설계가 막는 지점

| 지점 | 이전 동작 | 위치 |

## 사용자가 정한 것

| 항목 | 결정 |
|---|---|
| 글 저장 뒤 실패 | 세션을 남기고 차감하지 않는다. 한 장이라도 빠지면 미완수다 |
| 글 저장 뒤 사용자 취소 | 세션을 지우고 절반을 받는다. Claude 토큰을 이미 썼고, 공짜면 악의적인 사용자가 구독량을 소모시킬 수 있다 |
| 음성 실패 | 브라우저 보고를 믿는다. 요청을 조작하면 공짜로 쓸 수 있지만 받아들인다 |

## 설계자의 판단 (계획 승인으로 함께 승인됨)

1. 절반 차감을 글 저장 전 취소에도 적용한다. 사용자의 이유가 그대로 해당한다. 이전에는 전액 환불이라 시작과 취소를 반복하면 무한히 소모할 수 있었다.
2. 그림을 그리는 중의 세션 삭제는 거절한다. 삭제 버튼은 확인 없이 바로 지우므로, 받아 주면 경고 없이 100이 나가거나 취소를 공짜로 우회하는 길이 된다. 경고가 붙은 Cancel 한 길만 남긴다.
3. 실패한 시도는 내역 화면에 보이지 않는다. DB에는 `released` 행으로 남긴다. 행을 지우면 `credits.id`에 AUTOINCREMENT가 없어 번호가 재사용되고, 오래된 브라우저 보고가 같은 사람의 새 hold를 건드릴 수 있기 때문이다. 일부러 실패를 반복하는 계정을 운영자가 DB에서 찾을 수 있는 것도 이점이다. 과거의 `refund` 행은 그대로 두고 보여 준다.
4. Practice에서 말했는데 코치가 답하지 않으면 회가 닫힐 때 되돌린다. 새 타이머는 두지 않는다.

## 설계

### 왜 DB 트랜잭션 하나로 묶지 않는가

SQLite의 `BEGIN IMMEDIATE`를 제공자 호출 동안 유지하면, 수 초에서 수 분 동안 앱 전체의 쓰기가 막힌다. 그래서 2단계로 간다. 먼저 잔액을 잡아 두고(hold, 짧은 트랜잭션), 작업이 끝나면 확정(settle)하거나 되돌린다(release). 잡아 둔 금액은 잔액에서 빠져 있으므로 동시 요청이 잔액을 넘겨 쓸 수 없다.

### 데이터: 스키마 v14

`CREDITS` 상수는 v13 업그레이드가 쓰므로 고치지 않는다.

```sql
ALTER TABLE credits ADD COLUMN state TEXT NOT NULL DEFAULT 'settled' CHECK (state IN ('held', 'settled', 'released'));
ALTER TABLE credits ADD COLUMN open_until TEXT;
```

| `state` | `open_until` | 뜻 | 잔액에 포함 |
|---|---|---|---|
| `settled` | NULL | 확정 | 예 |
| `held` | NULL | 서버가 일하는 중 (동기 경로, job). 프로세스가 죽으면 다음 시작 때 되돌린다 | 예 |
| `held` | T | 브라우저의 연결 확인을 기다림. T가 지나면 무효 | T 전까지 |
| `settled` | T | 확정이지만 T까지는 브라우저가 끊김을 보고해 되돌릴 수 있음 | 예 |
| `released` | 무관 | 되돌림. 내역 화면에 보이지 않는다 | 아니오 |

기존 행은 기본값으로 `settled`가 되어 옮길 데이터가 없다. `session_cancelled` 종류가 새로 생기고 가격은 100이다.

### 서버

- 동기 경로: `paid` 문맥 관리자 안에서 일한다. 정상 종료면 확정, 어떤 예외든 되돌린다. 확정 실패는 로그만 남기고 응답을 살린다. 행은 다음 시작 때 되돌아가 사용자에게 유리하게 끝난다.
- 브라우저가 이어받는 경로: `browser_round`. 토큰 발급이 끝나면 연결 확인 기한(3분)을 건다. 응답에 `hold`가 실린다. 브라우저는 `POST /api/me/credits/holds/{id}/confirm`으로 연결을 알리고, 끊김 보고 기한(30분) 안에 `DELETE /api/me/credits/holds/{id}`로 되돌릴 수 있다. 둘 다 204, 해당 없으면 404. 3분은 Gemini 연결 창 2분과 setup 대기 10초에 여유를 더한 값이고, 30분은 Gemini 토큰 수명이다.
- 세션 job: 크레딧을 모른다. 끝나면 `on_finished`를 부르고, 값은 `api/sessions.py`가 정한다. `done`이고 그림 누락이 없으면 확정, `cancelled`이고 Claude를 불렀으면 `session_cancelled`로 확정, 나머지는 되돌린다. 취소로 끝나면 저장된 세션을 지운다. 운영자에게도 같다.
- 앱 시작: `held` 행을 모두 되돌린다. 앱이 시작될 때 살아 있는 job과 요청은 없고, uvicorn은 단일 프로세스다.
- 검사 순서는 그대로다: 401, 404/403, 503, 402. 운영자의 hold는 없다 (`None`).

### 브라우저

- 마이크를 토큰보다 먼저 받는다.
- 연결이 끝나면 확인을 보내고, 실패나 비정상 끊김이면 되돌림을 보낸다. 둘 다 오류를 무시하고 `keepalive`를 쓴다.
- 연결 중인 회는 `AbortSignal`로 멈출 수 있다. 멈추면 되돌린다.
- 취소 버튼은 Claude를 부른 뒤부터 가격을 보이고, 글이 저장된 뒤에는 `Cancel and delete`가 되어 세션이 지워진다고 알린다.

## 남는 한계

- 일부러 실패하게 만드는 주제로 세션 생성을 반복하면 Claude 사용량이 공짜로 나갈 수 있다. 실패는 차감이 없기 때문이다. 이번 범위에 제한을 넣지 않는다. 화면에는 보이지 않고, DB의 `released` 행으로 찾을 수 있다.
- 요청을 조작하면 음성을 공짜로 쓸 수 있다 (사용자가 받아들임).
- 연결 뒤 끊겼는데 인터넷까지 끊겨 보고가 못 나가면 차감이 남는다.
- 기한 만료는 이벤트가 없어 열린 탭의 알약이 다음 이벤트까지 낡을 수 있다.
- 피드백은 받았는데 무료 저장 호출이 실패한 경우(Practice), 같은 문장을 두 사람이 동시에 처음 들은 경우는 차감이 남는다.
- 지난 내역은 소급하지 않는다.
